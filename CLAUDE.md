# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Objetivo do projeto

Um quadro branco que mistura Excalidraw e draw.io: o desenho livre e o visual de esboço do Excalidraw, junto com a criação de diagramas estruturados do draw.io (formas conectadas, fluxogramas). Leve isso em conta ao modelar os elementos, por exemplo pensando em conexões entre formas e não só em formas soltas.

As funcionalidades podem seguir o Excalidraw, mas o visual da interface (toolbar, painéis, cores, seleção e alças) deve ser próprio, sem copiar o Excalidraw. O traço de esboço do `roughjs` nas formas continua.

O plano de desenvolvimento fica em [ROADMAP.md](ROADMAP.md), que guarda só o que falta fazer e as decisões que valem para todo item novo. Consulte-o antes de começar uma funcionalidade nova. Ao concluir um item, remova-o do ROADMAP e leve os detalhes de implementação para a mensagem de commit; se a mudança alterar a arquitetura ou uma convenção, atualize este arquivo.

## Comandos

- `npm run dev`: servidor de desenvolvimento do Vite com HMR
- `npm run build`: checagem de tipos (`tsc -b`, com project references) seguida de `vite build`, que gera `dist/`
- `npm run lint`: ESLint (flat config, em `eslint.config.js`)
- `npm run preview`: serve o build de produção

Não há test runner configurado. A checagem de tipos (`npx tsc -b`) é a principal verificação de correção. `noUnusedLocals` e `noUnusedParameters` estão ativos, então parâmetros não usados quebram o build. Prefixe-os com `_` ou remova-os.

## Stack

React 19 + TypeScript + Vite, com `react-router` v8 (data router), SCSS modules (`sass-embedded`), `zustand` para o estado, `roughjs` para o traço de esboço, `react-icons` (conjunto `lu`, Lucide) e `nanoid` para os IDs dos elementos. `react-color` é usado só pelas peças do seletor de cor livre (`CustomPicker`, `Saturation`, `Hue`). O projeto foi recomeçado recentemente (veja o histórico do git), então commits antigos descrevem outra arquitetura. Não se baseie neles.

Sobre o TypeScript: `verbatimModuleSyntax` está ativo, então imports só de tipos precisam usar `import type` ou o especificador `type`. Imports podem incluir a extensão `.tsx` (`allowImportingTsExtensions`).

## Arquitetura

É um quadro branco em um único `<canvas>` 2D. As formas são desenhadas com o `roughjs`, e a lógica fica em `src/lib/` (TypeScript puro, sem React). Os componentes só cuidam de interação e estado.

- **Rotas** ([src/main.tsx](src/main.tsx)): `createBrowserRouter` com `App` como layout (`<Outlet />`). `/` renderiza `Home`, a lista de boards, e `/board/:id` renderiza `Board` (`/board` sem id volta para `/`). As duas rotas têm loader: o de `/board/:id` ([boardRoute.ts](src/components/Board/boardRoute.ts)) grava o salvamento pendente, lê o board do `localStorage` e o entrega à rota, ou redireciona para `/` se o id não existir; o de `/` ([homeRoute.ts](src/components/Home/homeRoute.ts)) grava o salvamento pendente (`flushBoardSave`) e lê a lista. O `shouldRevalidate` do board só recarrega quando o id muda, porque recarregar zera o histórico.
- **Modelo** ([src/lib/elements/types.ts](src/lib/elements/types.ts)): `BoardElement` é uma união discriminada por `type` (`rectangle`, `ellipse`, `diamond`, `shape`, `compartments`, `table`, `arrow`, `freedraw`, `text`). Todo elemento tem `x, y, width, height` (a caixa delimitadora, sempre normalizada), além de `rotation`, `style` e `seed`. O `seed` é obrigatório: o roughjs sorteia o traço a cada desenho, e sem um seed fixo a forma "treme" a cada redesenho. Seta e lápis guardam `points` **relativos a `x, y`**, então mover qualquer elemento é só mudar `x` e `y`.
- **Formas** (`src/lib/elements/shapes/`): cada módulo exporta um `ShapeUtil` ([shapeUtil.ts](src/lib/elements/shapeUtil.ts)) com `draw`, `hitTest` e `resize`, além das funções de criação e atualização. [registry.ts](src/lib/elements/registry.ts) despacha pelo `type` e cuida do que é comum a todos, como a rotação, a busca do elemento sob o ponteiro e o deslocamento. Para adicionar uma forma: criar o módulo, incluir o tipo na união `BoardElement` e registrar o util em `shapeUtils` (o tipo mapeado faz o TypeScript reclamar se faltar).
- **Formas da biblioteca** ([shape.ts](src/lib/elements/shapes/shape.ts), [shapeKinds.ts](src/lib/elements/shapes/shapeKinds.ts)): o tipo `shape` tem um `kind` (`SHAPE_KINDS`), e cada formato define em `SHAPE_KIND_DEFINITIONS` o contorno fechado (`outline`), traços internos opcionais (`details`, como a tampa do cilindro), a área do rótulo e, se não forem os meios dos lados, os pontos de conexão. Com `bindToBox`, a borda das setas e o destaque usam a caixa em vez do contorno (o ator, cujo contorno é só a cabeça, e a chave; `getShapeBoundary`). O contorno pode ser aberto (`closed: false`, a chave `{`): aí não tem preenchimento e o clique só pega o traço. Um detalhe pode ser preenchido (`ShapeDetail.fill`): `"stroke"` pinta com a cor do contorno (círculo cheio, barra) e `"shape"` usa o preenchimento da forma, quando houver (as bolinhas da nuvem de pensamento); o clique dentro de um detalhe preenchido pega a forma. Com `solid`, o próprio contorno é pintado com a cor do traço e o preenchimento do estilo é ignorado (estado inicial, barra de bifurcação). Formatos de silhueta fixa (nuvem, estrela) são montados uma vez em coordenadas de 0 a 1 (`normalizeFigure`) e esticados para a caixa (`fitFigure`). Os contornos são `Figure` ([figure.ts](src/lib/geometry/figure.ts)): um `PathFigure` (retas e cúbicas), que vira SVG para o `rc.path` do roughjs com `preserveVertices` (sem isso o roughjs treme as pontas de cada trecho e as junções não se encontram), ou um `EllipseFigure`, desenhado com o `rc.ellipse`, para elipses saírem com o traço contínuo da elipse comum. Os dois são amostrados num polígono para o clique, a borda das setas e o destaque. `details` e `labelArea` recebem também a espessura do contorno, para vãos como o dos contornos duplos crescerem com ela. Os pontos de conexão são frações fixas da caixa (proporções como a inclinação do paralelogramo também são frações), para a ponta presa a um ponto não sair do contorno ao redimensionar. Com `labelRotation` (um quarto de volta), o rótulo é escrito girado dentro da área, como o título da raia horizontal (`-Math.PI / 2`, lido de baixo para cima). Os contêineres (raias e grupo com título) são formas comuns, com uma faixa de título de tamanho fixo em pixels (com teto pela metade da caixa) e sem vínculo com o que está dentro (para mover junto, agrupa-se; veja as decisões do ROADMAP). A piscina do BPMN é um item composto: o formato `pool` (com a mesma definição da raia horizontal) e as raias (`laneHorizontal`), todos no mesmo grupo. O [pool.ts](src/lib/elements/pool.ts) acha a piscina pela seleção (`getPoolTarget`: a piscina ou uma raia selecionada, pelo grupo mais interno) e insere ou apaga raias (`addPoolLane`/`removePoolLane`, pela ação `changePoolLanes` da store e pelo grupo "Piscina" da barra de estilo): a raia nova copia a de referência, a piscina cresce ou encolhe para baixo mantendo o topo (também girada), e as raias e o conteúdo abaixo do ponto de inserção (pelo centro, em coordenadas da piscina) descem ou sobem junto. É o único lugar em que um contêiner mexe no que está dentro. Retângulo, losango e elipse continuam tipos próprios, porque são ferramentas.
- **Compartimentos** ([compartments.ts](src/lib/elements/shapes/compartments.ts)): o tipo `compartments` (classe e interface UML; as entidades ER antigas continuam abrindo assim, mas a entidade nova é uma tabela) tem `sections` (só o texto de cada uma) e um `textStyle` próprio, sem `label`. A primeira seção é o cabeçalho, sempre em negrito e centralizado (`getSectionTextStyle`); as outras seguem o estilo, alinhadas no topo. A altura de cada seção não é guardada: sai do texto, e a última fica com a sobra da altura do elemento, então a forma estica na vertical e não encolhe além do texto. Mudanças de texto e de estilo passam por `fitCompartments`, que só aumenta a altura (mantendo o canto de cima quando girada). O texto é desenhado pelo `renderElement` (`drawCompartmentsText`), que esconde a seção em edição (`HiddenText`: `"label"` ou o índice da seção). O duplo clique edita a seção sob o cursor, e o `Enter` edita o cabeçalho.
- **Tabela** ([table.ts](src/lib/elements/shapes/table.ts)): o tipo `table` guarda as larguras das colunas (`columns`; a largura do elemento é a soma), as células (`cells: { text, fill? }[][]`), um `textStyle` único, `headerRow` (a primeira linha em negrito), `headerFill`, `title` (opcional: uma faixa no topo com a largura toda, em negrito, centralizada e com a cor do cabeçalho, usada pelo nome da entidade ER; nas funções de célula, o título é a linha `TITLE_ROW` (−1), então ele é editado, entra no `Tab` e tem pontos de conexão como uma linha, e a sobra da altura só vai para as linhas de dados) e `columnAligns` (opcional, o alinhamento de cada coluna, `null` herda o do `textStyle`; o estilo de cada célula sai de `getCellTextStyle(el, linha, coluna)`, e mudar o alinhamento pelo grupo "Texto" limpa os das colunas). A altura de cada linha não é guardada: sai do texto mais alto da linha, e a sobra da altura do elemento é repartida igualmente entre as linhas. Toda mudança passa por `fitTable`, que acerta a largura pela soma das colunas e só aumenta a altura, mantendo o canto de cima quando girada; inserir ou apagar uma linha soma ou tira a altura dela. Redimensionar escala as colunas. A cor de cada célula é a própria (`fill`), senão a do cabeçalho, senão o `fillColor` do estilo (o corpo); o tipo e a opacidade do preenchimento vêm do estilo, e cada célula é preenchida separadamente. O texto é desenhado pelo `renderElement` (`drawTableText`), que esconde a célula em edição (`HiddenText` aceita `{ row, column }`). A store guarda o cursor de célula (`tableCell`, fora do histórico), marcado ao clicar ou editar uma célula e desenhado sobre a tabela selecionada; o grupo "Tabela" da barra de estilo ([TableControls.tsx](src/components/Board/StyleBar/TableControls.tsx)) age sobre ele. A edição usa o `<textarea>` dos rótulos com `onTab`: `Tab` grava a célula e abre a seguinte (criando uma linha depois da última), `Shift+Tab` volta. Arrastar uma borda interna entre colunas é a `Interaction` `resizingColumn`. Cada célula pode ter um `textStyle` parcial (`CellTextStyle`: negrito, itálico, sublinhado, cor e alinhamentos, `CELL_TEXT_KEYS`) que se sobrepõe ao alinhamento da coluna e ao estilo da tabela; `setCellsTextStyle` remove as chaves iguais ao estilo de base, para a sobreposição não guardar o que já herda. O grupo "Texto" tem um alcance para tabelas (`tableTextScope` na store, "tabela inteira" ou "células selecionadas"): no das células, o `setTextStyle` da store e os seletores de texto agem na célula ativa ou no intervalo (`getCellTextTarget`), e a fonte e o tamanho ficam escondidos; no da tabela, mudar uma propriedade limpa a sobreposição dela nas células (`clearCellTextStyles`, no `applyTextStyle`). Células mescladas: a célula de origem guarda `rowSpan` e `colSpan`, e as cobertas não guardam nada; quem cobre quem sai de `getCoverage` (com cache por array de células), e as funções que recebem uma posição a resolvem para a origem (`resolveCell`), então clicar, editar ou colorir uma célula coberta age na mesclada. O texto de uma célula que cobre várias linhas reparte o que faltar de altura entre elas, e as bordas internas são desenhadas em trechos que pulam as células mescladas. Inserir uma linha ou coluna dentro de uma mesclagem a aumenta, e apagar a diminui (apagar a da origem passa a origem para a seguinte). Com a tabela selecionada, `Shift+clique` marca um intervalo (`extent` no cursor de célula), que cresce para não cortar mesclagens (`getMergeRange`). Os pontos de conexão são o meio de cima, o de baixo e os dois lados de cada linha (`getTableConnectionPoints`, frações que mudam com as alturas). A ponta solta num ponto de linha guarda o índice da linha na ligação (`ArrowBinding.row`), e o `keepFixedAnchor` recalcula a fração a partir dele, com a folga horizontal; inserir ou apagar uma linha pelo grupo "Tabela" renumera essas ligações no mesmo passo do histórico (`remapTableRowBindings`), e a ligação da linha apagada perde o `row` e vai para o ponto mais próximo. Colar texto com tabulação cria uma tabela (`parseTableText`, no `createPastedText` do Canvas), com as colunas medidas pelo texto.
- **Biblioteca** ([library.ts](src/lib/elements/library.ts), [Library/](src/components/Board/Library/)): `LIBRARY_GROUPS` e `LIBRARY_ITEMS` são o catálogo único (id, nome, grupo, palavras de busca, tamanho e `create`, que recebe a caixa e o estilo de texto atual e devolve uma ou mais partes `{ element, style? }`; o `style` da parte sobrepõe o estilo atual, como o contorno tracejado do atributo derivado e da linha de vida, ou o branco sólido da ativação). Os ajudantes `box`, `shape` e `compartments` montam os itens comuns, já com rótulo quando o texto faz parte da forma (o nome do ator, o título da fronteira do sistema; o rótulo pode trocar o alinhamento, como o campo de texto do wireframe, alinhado à esquerda). Itens compostos (participante, checkbox, cartão) são funções que montam várias partes, inclusive textos soltos (`createText`), e saem agrupados. `createLibraryElements` aplica o estilo e agrupa quando há mais de um elemento. As prévias desenham em tamanho real e reduzem com `ctx.scale`, e são redesenhadas quando as fontes carregam. O painel lateral (`libraryOpen` na store, salvo nas preferências) desenha as prévias com o mesmo `renderElement`, insere no centro com um clique ou arrastando (arraste nativo do HTML com o tipo `LIBRARY_DRAG_TYPE`, recebido pelo Canvas). O centro vem do `viewportSize`, que o Canvas mede e guarda na store (o zoom pelos botões também o usa).
- **Setas ligadas** ([src/lib/elements/bindings.ts](src/lib/elements/bindings.ts)): `ArrowElement` tem `startBinding`/`endBinding` (`{ elementId, anchor, fixed }`). As formas que aceitam ligação implementam `getBorderOffset` e `getConnectionPoints` (pontos fixos relativos, que viram o `anchor`) no `ShapeUtil`. A store chama `updateBoundArrows` dentro de `updateElements`, `replaceElement` e `deleteElements`, então qualquer mudança numa forma já reposiciona as setas ligadas a ela. Não recalcule ligações nas interações. Toda ponta ligada sai de um ponto de conexão. Com `fixed: true` (a ponta foi solta sobre o ponto), o ponto fica preso; com `fixed: false` (solta no corpo da forma), o recálculo troca o `anchor` pelo ponto virado para a outra ponta. As interações ligam pontas com `bindArrowEnd`, que trata os laços (as duas pontas na mesma forma). O `updateBoundArrows` recebe os elementos de antes para mover os pontos do meio de um laço junto com a forma. A seta tem `routing` (`straight`, `curved` ou `elbow`). Na reta e na curva, os pontos do meio são do usuário (alças do meio em `getArrowHandles`), e a curva é uma Catmull-Rom que passa por eles (`getArrowPath` amostra a curva para clique e caixa). Na ortogonal, os pontos do meio são derivados das pontas pelo `refreshArrow` (rota em [src/lib/geometry/orthogonalRoute.ts](src/lib/geometry/orthogonalRoute.ts)). Os trechos que o usuário arrastou ficam em `fixedSegments`, e o recálculo liga as pontas e os trechos fixos com pedaços de rota automática. As pontas têm formato próprio (`startArrowhead`/`endArrowhead`), com a geometria pura em [src/lib/elements/arrowheads.ts](src/lib/elements/arrowheads.ts), usada pelo canvas e pelos ícones do painel. Formatos novos entram em `ARROWHEADS` e em `getArrowheadParts`.
- **Rótulos**: retângulo, elipse, losango, as formas `shape` e a seta têm um `label` opcional (`{ text, textStyle }`, veja `isLabeledElement`), desenhado e testado no clique de forma comum em `registry.ts` (`getLabelLayout`). Cada forma define a área do texto com `getLabelArea` e, se o texto for girado, o ângulo com `getLabelRotation`. O `getLabelArea` do registry já devolve a área do texto girado (largura e altura trocadas, com o mesmo centro), o `LabelLayout` traz a `rotation`, e o desenho, o clique e o `<textarea>` (no `editorLayout` do Canvas, somando a rotação da forma) giram em torno do centro dessa área. Na seta, a área é uma faixa de altura zero sobre o caminho, na fração `labelPosition` do comprimento (padrão 0,5, o meio; arrastar o texto da seta selecionada muda essa fração), e o `renderElement` recorta a linha atrás do texto com `ctx.clip`. A quebra de linha (`wrapText` em [src/lib/text.ts](src/lib/text.ts)) imita o `<textarea>` com `pre-wrap`; se mudar uma, mude a outra.
- **Grade de fundo** ([src/lib/render/grid.ts](src/lib/render/grid.ts)): só visual, sem encaixe (o snap foi testado e descartado). `showGrid` e `gridStyle` (`dots` ou `lines`) ficam na store e são salvos. O `renderScene` desenha a grade antes dos elementos.
- **Coordenadas** ([src/lib/viewport.ts](src/lib/viewport.ts)): os elementos vivem em coordenadas de mundo, e os eventos chegam em coordenadas de tela (pixels CSS relativos ao canvas), com `tela = mundo * zoom + offset`. Converta os pontos do ponteiro com `screenToWorld` antes de criar ou alterar elementos. `renderScene` aplica o viewport e o `devicePixelRatio` via `ctx.setTransform`, então os `draw` desenham direto em coordenadas de mundo. Tamanhos que devem ser constantes na tela (alças, folga de clique, linhas da seleção) são definidos em pixels e divididos por `zoom`. O zoom pelos botões e atalhos do `ZoomIndicator` anda pelos níveis de `ZOOM_STEPS` (`stepZoom`/`resetZoom` da store, centrados no meio do canvas, pelo `viewportSize`); a roda e a pinça continuam livres.
- **Seleção** ([src/lib/selection.ts](src/lib/selection.ts)): o quadro da seleção (`SelectionFrame`, caixa sem rotação mais o ângulo; gira junto quando há um elemento só), as 8 alças, a alça de rotação e a matemática de redimensionar e girar. `getElementBounds` é a caixa alinhada aos eixos, já considerando a rotação; `getElementBox` é a caixa sem rotação. Setas nunca têm `rotation`: girá-las gira os pontos. [renderScene.ts](src/lib/render/renderScene.ts) desenha essa camada por cima dos elementos. Durante o redimensionamento e a rotação, o Canvas preenche o `measurement` do overlay, e [measurement.ts](src/lib/render/measurement.ts) desenha a pílula com as dimensões ou o ângulo.
- **Persistência** ([src/lib/persistence.ts](src/lib/persistence.ts)): cada board fica numa chave própria do `localStorage` (`whiteboard:board:<id>`, com `name`, `elements` e `viewport`), listado no índice `whiteboard:boards` (id, nome, criação e última edição). As preferências da grade, do painel da biblioteca (aberto e grupos recolhidos, `collapsedLibraryGroups`) e do tema ficam à parte, em `whiteboard:preferences`. A persistência é responsabilidade só deste app: quando o board virar biblioteca npm, ela não vai gravar nada (veja as decisões do ROADMAP), então não leia nem grave o `localStorage` fora do `persistence.ts` e dos módulos do app [appBoardSaving.ts](src/store/appBoardSaving.ts) (salvamento do board com debounce, `flushBoardSave`, o `pagehide` e o aviso de falha, `onBoardSaveFailure`) e [appPreferences.ts](src/store/appPreferences.ts) (as preferências do app, `useAppPreferences`, gravadas a cada mudança). O board aberto não sabe onde é guardado: a rota `Board` ([Board.tsx](src/components/Board/Board.tsx)) passa o conteúdo lido pelo loader como `initialData` do `Whiteboard` (com `key` pelo id) e salva no `onChange`; ela também cuida do título da página e do aviso de armazenamento cheio. O board pode ser exportado e importado como `.whiteboard.json` (`serializeBoardFile`/`parseBoardFile`; o download e a escolha do arquivo ficam em [src/lib/boardFile.ts](src/lib/boardFile.ts), e as ações da interface em [boardFileActions.ts](src/components/Board/boardFileActions.ts)). O nome do board (`name` na store, editado no [BoardTitle](src/components/Board/BoardTitle/BoardTitle.tsx)) vai nos dois e dá nome ao arquivo baixado. Os dois usam a mesma validação: ao mudar o modelo dos elementos, ajuste o `isValidElement`. Sem versão nem migração durante o desenvolvimento.
- **Exportar imagem** ([src/lib/export/](src/lib/export/)): PNG e SVG usam o mesmo `renderElement` do canvas. O SVG passa um `SvgContext` (imitação parcial do `CanvasRenderingContext2D`) no lugar do contexto, e o roughjs recebe um canvas falso que devolve esse contexto. Se uma forma passar a usar uma operação do contexto que o `SvgContext` não tem, acrescente-a lá. As fontes do SVG são embutidas como subconjunto do Google Fonts ([fonts.ts](src/lib/export/fonts.ts)). O diálogo fica em [Export/](src/components/Board/Export/).
- **Estado e histórico** ([src/store/boardStore.ts](src/store/boardStore.ts)): a store é criada por instância (`createBoardStore`, com o `createStore` do zustand), sem efeitos ao importar o módulo nem acesso ao `localStorage`, e entregue pelo `BoardStoreContext` ([boardStoreContext.ts](src/store/boardStoreContext.ts)). Os componentes leem com `useBoardStore(selector)`, e quem precisa do estado atual num handler pega a instância com `useBoardStoreApi()` e chama `getState()`. Funções fora de componentes (helpers do Canvas, `boardFileActions`, `insertLibraryItem`, `toggleColorScheme`) recebem a instância (`BoardStore`) como primeiro parâmetro; não importe uma instância global dentro do board. Quem cria e entrega a store é o componente `Whiteboard` ([Whiteboard.tsx](src/components/Board/Whiteboard.tsx)), o que vai ser a API pública da biblioteca: ele cria uma instância com a cena e as preferências iniciais (`initialData`, `initialPreferences`; só valem na montagem), avisa das mudanças por `onChange(scene, info)` e `onPreferencesChange`, recebe o botão de voltar por prop (`back`) e expõe um ref (`WhiteboardApi`: `getScene`, `updateScene`, `undo`, `redo`, `resetHistory`, `exportPng`). Ele não conhece rotas, `localStorage` nem o título da página. Todo elemento tem um `version` (ausente vale 0), que o `set` da store sobe sozinho para cada elemento cujo objeto mudou (`bumpVersions`); não incremente à mão. O mesmo vale para o `index`, a posição na ordem de desenho como chave fracionária que ordena como texto ([fractionalIndex.ts](src/lib/elements/fractionalIndex.ts), sem dependência externa): a ordem continua sendo a do array, e o `set` (e a criação da store) passa os elementos pelo `syncIndices`, que mantém a maior sequência crescente de índices válidos e só gera chaves novas para os que ficaram fora dela (os que mudaram de lugar, os novos e os sem índice, como os de boards antigos). Assim reordenar, agrupar, colar ou duplicar não precisa saber de índices. O mesmo `set` preenche o `lastChange` (`reason`, `changedIds`, `seq`), que o `Whiteboard` repassa ao `onChange`: um aviso por passo do histórico (`commit`, ou `undo`/`redo`, pelo `setWithReason`), juntando os ids alterados desde o passo anterior, e um nas trocas de nome e de viewport. Uma ação contínua que estende o último passo sem registrar outro (a seta do teclado segurada) usa `setWithReason("commit", ...)` para avisar mesmo assim. O `updateScene` (cena vinda de fora, `reason: "external"`) zera o histórico (`history: "clear"`, o padrão) ou vira um passo (`"record"`), solta as setas presas a formas que sumiram e limpa a seleção, o `editingGroupId` e o `tableCell` (`sanitizeTransient`, usado também ao apagar, desfazer e refazer). Ele nunca é aplicado no meio de uma interação: a store conta as interações em andamento (`beginInteraction`/`endInteraction`) e guarda as cenas numa fila até o contador voltar a zero. Quem guarda um `before` e chama `commitHistory` no fim precisa avisar o começo e o fim: o Canvas faz isso nos arrastes (`holdInteraction`/`releaseInteraction`, soltando depois do `commitHistory`) e enquanto há texto em edição, e as prévias de estilo (`useStylePreview`) e da tabela (`useTablePreview`) também. Uma interação nova desse tipo deve fazer o mesmo, senão uma cena de fora pode ser sobrescrita pelo arraste ou desfeita pelo próximo `Ctrl+Z`. A store tem `elements`, `selectedIds`, `tool`, `viewport` e o histórico (`past`/`future`, snapshots imutáveis de `elements`). Ações discretas (`addElement`, `replaceElement`, `deleteElements`, `groupSelection`, `ungroupSelection`) já registram um passo. Ações contínuas usam `updateElements` sem registrar, e quem chama guarda `elements` no início do arraste e chama `commitHistory(before)` no fim. Sempre crie arrays e objetos novos ao alterar elementos, porque o histórico depende de imutabilidade.
- **Canvas** ([src/components/Board/Canvas/Canvas.tsx](src/components/Board/Canvas/Canvas.tsx)): é dono do `<canvas>` e dos eventos de ponteiro, roda e espaço. Cada arraste é uma `Interaction` (união discriminada em um ref): pan, criação, lápis, mover, redimensionar ou seleção por caixa. Estado transitório (rascunho, caixa de seleção, texto em edição) fica local no Canvas, não na store. Os handlers leem a store com `boardStore.getState()` (a instância do `useBoardStoreApi()`) para não depender de closures antigas. A roda usa um listener nativo com `passive: false`, porque o `onWheel` do React não permite `preventDefault`.
- **Texto** ([TextEditor.tsx](src/components/Board/TextEditor/TextEditor.tsx), [src/lib/text.ts](src/lib/text.ts)): a edição usa um `<textarea>` posicionado sobre o canvas, e o elemento em edição é escondido do canvas. No layout `label`, o textarea gira em torno do `pivot` (o centro da forma), não do próprio centro, porque a área do texto nem sempre é centrada na forma. Todo texto (solto, rótulo, seta e compartimentos) tem um `TextStyle` (família, tamanho, cor, negrito, itálico, sublinhado e alinhamentos; `underline` é opcional e falso quando ausente). Todo texto do canvas é desenhado pelo `drawTextLines` ([src/lib/text.ts](src/lib/text.ts)), que também traça o sublinhado: o canvas não sublinha sozinho, então o traço fica a `UNDERLINE_OFFSET` da linha de base real das letras (medida com `alphabeticBaseline`), a mesma distância que o `<textarea>` usa no `text-underline-offset` (com `text-decoration-skip-ink: none`, porque o canvas atravessa as descendentes). `fontString`, `LINE_HEIGHT`, `measureText` e `layoutText` recebem esse estilo e são compartilhados entre o canvas e o textarea, para os dois ficarem alinhados. A cor `null` herda o `strokeColor` do elemento (`resolveTextColor`). Mudanças de estilo de texto passam por `applyTextStyle` ([src/lib/elements/textStyle.ts](src/lib/elements/textStyle.ts)), que remede o texto solto e reajusta a altura dos `compartments`.
- **Barra de estilo** ([StyleBar.tsx](src/components/Board/StyleBar/StyleBar.tsx)): barra flutuante renderizada pelo Canvas acima da seleção (ou no topo, com uma ferramenta de desenho ativa e nada selecionado), escondida durante arrastes e edição de texto. Cada botão abre um submenu (`Popover`) com os controles de um grupo ([StyleControls.tsx](src/components/Board/StyleBar/StyleControls.tsx)): contorno, preenchimento e seta. O estilo tem campos separados para contorno (`stroke*`) e preenchimento (`fill*`), e as formas de caixa desenham os dois em etapas separadas (`drawFillAndStroke`). O que cada tipo de elemento aceita fica em [src/lib/elements/style.ts](src/lib/elements/style.ts) (`supportsStyle`). Os cantos (`corners`, `sharp` ou `round`) são opcionais no estilo (ausente é reto), para os boards salvos antes continuarem válidos, e só o retângulo e o losango os aceitam. Os seletores leem o estilo pelo `styleValue`, que cai no `DEFAULT_STYLE` quando o campo falta. O raio do retângulo é fixo em pixels (com teto), porque os pontos de conexão são os meios dos lados; no losango, o corte é uma fração do lado, para os pontos de conexão (no meio dos arcos das pontas) continuarem frações fixas da caixa. Uma ponta presa (`fixed`) a um ponto que deixou de existir, como a ponta do losango ao arredondar, vai para o ponto atual mais próximo (`keepFixedAnchor`), e o `setStyle` reposiciona as setas quando os cantos mudam. O estilo das próximas formas é o `currentStyle` da store, aplicado na criação pelo Canvas. Mudanças contínuas (seletor de cor, hex, opacidade) usam `setStyle(patch, { record: false })` e um `commitHistory` no fim (`useStylePreview`). Os seletores do zustand ([selectors.ts](src/components/Board/StyleBar/selectors.ts)) devolvem valores simples (string, número), não arrays novos, para não re-renderizar à toa.
- **Cabeçalho do board**: no canto superior esquerdo, o botão de voltar (só quando o `Whiteboard` recebe `back`; no app, "Todos os boards") e o menu do board ([BoardMenu.tsx](src/components/Board/BoardMenu/BoardMenu.tsx): abrir e salvar arquivo, exportar imagem e renomear), seguidos do nome. Ações sobre o board inteiro entram nesse menu, não na toolbar, que fica só com ferramentas, edição e grade (e rola se não couber na altura).
- **Duplicar e área de transferência**: `cloneElements` ([src/lib/elements/clone.ts](src/lib/elements/clone.ts)) dá IDs e `seed` novos às cópias e religa as setas às cópias das formas quando as duas foram copiadas (a ponta ligada a uma forma de fora fica solta). Copiar, recortar e colar usam os eventos `copy`/`cut`/`paste` da raiz do board ([useClipboard.ts](src/components/Board/Canvas/useClipboard.ts)), não o `keydown`, com um JSON `{ type: "whiteboard", elements }` (`serializeClipboard`/`parseClipboard`, com a mesma validação do arquivo), então colar funciona entre boards e abas e aceita o conteúdo de um `.whiteboard.json`. Colar põe os elementos centrados no cursor (ou no meio da tela), e texto comum vira um texto solto. Um `paste` que chega com o botão do meio pressionado ou logo depois de soltá-lo é ignorado: no Linux é a colagem da seleção primária, que o navegador entrega como `paste`, e no quadro o botão do meio só arrasta a tela. A store tem `insertElements` (vários elementos num passo, já selecionados) e `translateElements` (mover pelo teclado; com `record: false` nas repetições da tecla segurada, para virar um passo só).
- **Grupos** ([src/lib/elements/groups.ts](src/lib/elements/groups.ts)): cada elemento pode ter `groupIds`, do grupo mais interno para o mais externo (ausente quando não está em grupo). A seleção continua sendo uma lista de IDs de elementos: o clique e a caixa expandem para a "unidade" do elemento (`getSelectionUnit`, o grupo mais externo abaixo do `editingGroupId`), e a caixa só pega grupos inteiros. O `editingGroupId` da store é o grupo em que o usuário entrou com duplo clique; clicar fora dele, no vazio ou trocar de ferramenta sai, e o `Esc` sobe um nível (`exitEditingGroup`). Agrupar insere o grupo novo logo abaixo do `editingGroupId` e junta os membros na ordem de desenho, sobre o mais alto deles. Duplicar dentro de um grupo mantém as cópias nele (`cloneElements` recebe o grupo a manter), e colar sempre gera grupos novos (`remapGroupIds`). Mover, redimensionar e girar não sabem de grupos: agem sobre a seleção já expandida. A ordem de desenho é a ordem do array `elements` (o `index` de cada elemento acompanha, veja "Estado e histórico"), e `reorderElements` ([order.ts](src/lib/elements/order.ts)) leva a seleção para a frente, para o fundo ou um passo (pulando a próxima unidade que se sobrepõe à seleção pela caixa). Ela trabalha com as unidades da seleção, então um grupo anda como um bloco, e dentro de um grupo em edição só reordena os membros dele, nas posições que eles já ocupam. Os atalhos (`Ctrl+]`, `Ctrl+[`, com `Shift` para frente e fundo) leem o `e.key` (`]`/`}` e `[`/`{`), não o `e.code`, porque no ABNT2 os colchetes ficam em outras teclas físicas.
- **Toolbar e atalhos**: [tools.ts](src/components/Board/Toolbar/tools.ts) é a fonte única das ferramentas (ícone, nome e teclas), usada pela toolbar, pela ajuda e por [useShortcuts.ts](src/components/Board/useShortcuts.ts). Os demais atalhos ficam em [shortcuts.ts](src/components/Board/shortcuts.ts) (nome e teclas, mais `formatShortcut` para os tooltips), lidos pelos tooltips e pela ajuda ([Help/](src/components/Board/Help/)). O `useShortcuts` trata as teclas à mão: ao criar ou mudar um atalho, atualize os dois. Os atalhos ignoram teclas digitadas em campos de texto (`isTypingTarget`).
- **Foco e teclado**: o board não ouve teclas nem a área de transferência no `window` ou no `document`, para não capturar o que é da página hospedeira. A raiz do `Whiteboard` é focável (`tabIndex={-1}`, sem contorno) e entregue pelo `BoardRootContext` ([boardRoot.ts](src/components/Board/boardRoot.ts)); o `useShortcuts`, as teclas do Canvas (espaço, Enter e Shift) e o `useClipboard` ouvem nela, então só funcionam com o foco dentro do board. Com `autoFocus` (desligado por padrão; o app liga), a raiz recebe o foco ao montar. Como o `pointerdown` do canvas chama `preventDefault`, ele foca a raiz à mão (`focusBoard`). Para os atalhos não pararem quando o elemento focado some, o foco volta à raiz ao sair do texto pelo teclado, ao terminar de editar o nome e no `Enter` do tamanho da fonte; o `Popover` devolve o foco ao botão que o abriu quando fecha com o foco dentro dele; e, como rede de segurança, um `focusout` na raiz devolve o foco ao board quando o elemento que o perdeu saiu da tela e o foco caiu no `body` (clicar numa área da página hospedeira não é afetado, porque o elemento continua lá). Ao criar um campo ou botão que some sozinho, siga o mesmo cuidado. O espaço solto fora do board (`focusout` para fora) desarma o pan. O `Esc` do `Popover` com o foco fora dele (num botão do board) é tratado na captura, para não limpar a seleção junto.
- Tipos primitivos compartilhados (`Point`) ficam em `src/lib/types.ts`, e a geometria pura em `src/lib/geometry/` (`bounds.ts`, `distance.ts`, `constrain.ts`).
- **Primitivos de UI** (`src/ui/`): componentes visuais pequenos e reutilizáveis (`IconButton` com tooltip e atalho, `Tooltip`, `Popover`, `Menu` (lista de ações sobre um `Popover`, com navegação pelas setas; um item com `checked` vira opção marcável, como no menu de tema), `Modal`, `Toast`, `Button` (padrão, primário e perigo), `InlineEdit` (texto que vira campo com duplo clique), `Panel`/`PanelSection`, `Divider`). Botões de ícone novos devem usar o `IconButton`, e os que abrem um `Popover` passam `hasPopup` (marcador no canto e `aria-expanded`; com `popupRole="menu"` quando abrem um `Menu`). O `Modal` cuida do foco (preso enquanto aberto) e barra os atalhos do board com `stopPropagation`. `Popover`, `Tooltip` e `Modal` vão para o contêiner do `PortalContainerContext` ([portal.ts](src/ui/portal.ts)), ou o `body` sem ele: o `Whiteboard` põe esse contêiner dentro da própria raiz (marcado com `data-portal-container`), para os portais herdarem as variáveis do tema; como são `position: fixed` e a raiz não tem `transform` nem `contain`, continuam posicionados pela janela (e podem passar da borda do board). Os eventos nativos dos portais agora passam pela raiz antes dos handlers do React, então os listeners de teclado e da área de transferência do board ignoram o que vem de dentro de um portal (`isInPortal`), senão as setas do `Menu` moveriam a seleção e o `?` da ajuda abriria e fecharia ao mesmo tempo. Não ponha `transform`, `filter` ou `contain` na raiz do board. O `IconButton` mantém o foco depois do clique (a dica por foco só aparece no foco por teclado, `:focus-visible`), em vez de dar `blur`, que jogaria o foco no `body` e desligaria os atalhos.
- **Tema** ([src/lib/theme.ts](src/lib/theme.ts)): fonte única de cores, fontes, raios e sombras, com dois temas (`lightTheme` e `darkTheme`, cada um com o seu `scheme`). `themeVariables` vira cada valor em variável CSS com o prefixo `--wb-` (`--wb-color-*`, `--wb-canvas-*`, `--wb-font-*`, `--wb-radius-*`, `--wb-shadow-*`), para não colidir com as da página hospedeira. O `Whiteboard` aplica as variáveis do tema ativo e o `color-scheme` como `style` da própria raiz (sem tocar no `document`), e a raiz tem fundo, cor, fonte e um reset mínimo próprios (com `:where()`, de especificidade zero, para não sobrepor as classes dos componentes), então o board não depende do CSS global do app. O app aplica o mesmo tema no `documentElement` com o `applyTheme` (o `main.tsx` aplica o inicial e o `App` reaplica quando ele muda), para a home e o `body`. A preferência é o `themeMode` (`light`, `dark` ou `system`): dentro do board, o da store, lido pelo `useColorScheme`/`useTheme` ([useColorScheme.ts](src/components/useColorScheme.ts)); no app (o `App`, que aplica o tema na página, e as miniaturas da home), o do `useAppPreferences`, que o board atualiza pelo `onPreferencesChange`. Os dois passam pelo `useResolvedColorScheme`, que ouve o `prefers-color-scheme` no modo `system`. O canvas não lê um tema fixo: o `renderScene` recebe o `Theme` ativo e repassa as cores à grade, à medida e à seleção. Não escreva cores, fontes ou sombras soltas em SCSS ou no canvas: use as variáveis ou acrescente um token aos dois temas. A paleta de cores oferecida aos elementos fica em `lightTheme.palette` (com `paper`, o branco usado para formas que cobrem o que está atrás, como a ativação da sequência), e o tema escuro usa a mesma.
- **Cores no tema escuro** ([src/lib/colors.ts](src/lib/colors.ts), [elementColors.ts](src/lib/elements/elementColors.ts)): os elementos guardam sempre as cores do tema claro. O `renderElement` recebe o `ColorScheme` e, no escuro, desenha uma cópia do elemento com as cores trocadas por `adaptColor`, que inverte a luminosidade (HSL) numa faixa entre o fundo escuro e o quase branco e mantém o matiz e a saturação. A cópia é guardada num `WeakMap` por elemento, o que funciona porque o modelo é imutável. Uma cor nova no modelo (como o `headerFill` e o `fill` das células) precisa entrar no `adaptElement`. O que mostra a cor de um elemento na interface (o `<textarea>` do texto em edição e as amostras da barra de estilo) passa por `adaptColor`, mas o valor escolhido e salvo continua o claro. A exportação usa o esquema do `ExportOptions` (o fundo "Escuro" do diálogo), e as miniaturas da lista e da biblioteca seguem o tema ativo.
- **Fontes**: as três vêm do Google Fonts numa única folha (`display=swap`), todas com licença SIL Open Font License. O endereço é o `FONT_STYLESHEET_URL` ([src/components/fonts.ts](src/components/fonts.ts)): o `Whiteboard` acrescenta o `<link>` ao `head` sozinho (`useFontStylesheet`, num efeito; a prop `loadFonts={false}` desliga, para quem hospeda as fontes por conta própria ou tem CSP), a não ser que já exista um com o mesmo endereço, como o do [index.html](index.html), que o app mantém para a home. Os dois endereços precisam ser iguais.
  - **Caveat** (pesos 400 a 700, variável, sem itálico; o navegador inclina sozinho): token `theme.font.hand` (`--font-hand`). Texto no canvas com a chave `hand`, a padrão.
  - **IBM Plex Sans** (400, 500, 600 e 700, mais itálico 400 e 700): token `theme.font.ui` (`--font-ui`). Fonte da interface (`src/index.css`; os pesos 500 e 600 são dela) e texto no canvas com a chave `sans` (400, 700 e os itálicos).
  - **IBM Plex Mono** (400, 500 e 700, mais itálico 400 e 700): token `theme.font.mono` (`--font-mono`). Na interface, atalhos dos tooltips, badges e campos de hex e tamanho (peso 500); no canvas, a chave `mono`.
  - No canvas, a chave do `TextStyle` vira a família por `FONT_STACKS` ([src/lib/text.ts](src/lib/text.ts)). O `useFontsVersion` (um contador único para a página, lido com `useSyncExternalStore`) pré-carrega todas as combinações de `FONT_FAMILIES` com negrito e itálico, de novo quando a folha injetada termina de carregar, e sobe a cada `loadingdone`; o Canvas, a biblioteca e as miniaturas redesenham quando ele muda, para nenhum texto ficar com a fonte reserva.
  - Para trocar ou acrescentar uma fonte ou um peso: ajustar o `FONT_STYLESHEET_URL` e o `<link>` do `index.html` (iguais), o token em `theme.font` e, se for fonte de texto do canvas, a chave em `FONT_FAMILIES` (`types.ts`), o `FONT_STACKS`, o `GOOGLE_FONTS` da exportação SVG ([src/lib/export/fonts.ts](src/lib/export/fonts.ts)) e o nome no grupo "Texto" da barra de estilo (`TextControls.tsx`).

Estilos: os componentes usam arquivos `*.module.scss` na mesma pasta. Os estilos globais ficam em `src/index.css` e `src/App.css`.

## Convenções

- **Não escreva comentários no código**, nem de linha, nem de bloco, nem JSDoc, em `.ts`, `.tsx` e `.scss`. O código deve se explicar pelos nomes. O motivo das decisões fica nas mensagens de commit (com os detalhes de implementação) e, quando a decisão orienta o trabalho futuro, na seção "Decisões tomadas" do [ROADMAP.md](ROADMAP.md). Se um bloco só fazia sentido com um comentário (por exemplo, um `catch` vazio), reescreva o código para não precisar dele.
- Mensagens de commit e alguns identificadores são escritos em português (pt-BR).
- Componentes usam named exports (`export function Board()`). A exceção é `App`, que é export default.
