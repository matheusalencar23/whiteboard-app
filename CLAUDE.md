# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Objetivo do projeto

Um quadro branco que mistura Excalidraw e draw.io: o desenho livre e o visual de esboço do Excalidraw, junto com a criação de diagramas estruturados do draw.io (formas conectadas, fluxogramas). Leve isso em conta ao modelar os elementos, por exemplo pensando em conexões entre formas e não só em formas soltas.

As funcionalidades podem seguir o Excalidraw, mas o visual da interface (toolbar, painéis, cores, seleção e alças) deve ser próprio, sem copiar o Excalidraw. O traço de esboço do `roughjs` nas formas continua.

O plano de desenvolvimento fica em [ROADMAP.md](ROADMAP.md), que guarda só o que falta fazer e as decisões que valem para todo item novo. Consulte-o antes de começar uma funcionalidade nova. Ao concluir um item, remova-o do ROADMAP e leve os detalhes de implementação para a mensagem de commit; se a mudança alterar a arquitetura ou uma convenção, atualize este arquivo.

## Comandos

- `npm run dev`: servidor de desenvolvimento do Vite com HMR
- `npm run build`: checagem de tipos (`tsc -b`, com project references) seguida de `vite build`, que gera `dist/`
- `npm run lint`: ESLint (flat config, em `eslint.config.js`)
- `npm run preview`: serve o build de produção

Não há test runner configurado. A checagem de tipos (`npx tsc -b`) é a principal verificação de correção. `noUnusedLocals` e `noUnusedParameters` estão ativos, então parâmetros não usados quebram o build. Prefixe-os com `_` ou remova-os.

## Stack

React 19 + TypeScript + Vite, com `react-router` v8 (data router), SCSS modules (`sass-embedded`), `zustand` para o estado, `roughjs` para o traço de esboço, `react-icons` (conjunto `lu`, Lucide) e `nanoid` para os IDs dos elementos. `react-color` é usado só pelas peças do seletor de cor livre (`CustomPicker`, `Saturation`, `Hue`). O projeto foi recomeçado recentemente (veja o histórico do git), então commits antigos descrevem outra arquitetura. Não se baseie neles.

Sobre o TypeScript: `verbatimModuleSyntax` está ativo, então imports só de tipos precisam usar `import type` ou o especificador `type`. Imports podem incluir a extensão `.tsx` (`allowImportingTsExtensions`).

## Arquitetura

É um quadro branco em um único `<canvas>` 2D. As formas são desenhadas com o `roughjs`, e a lógica fica em `src/lib/` (TypeScript puro, sem React). Os componentes só cuidam de interação e estado.

- **Rotas** ([src/main.tsx](src/main.tsx)): `createBrowserRouter` com `App` como layout (`<Outlet />`). `/` renderiza `Home`, a lista de boards, e `/board/:id` renderiza `Board` (`/board` sem id volta para `/`). As duas rotas têm loader: o de `/board/:id` ([boardRoute.ts](src/components/Board/boardRoute.ts)) carrega o board na store antes de renderizar (`loadStoredBoard`) e redireciona para `/` se o id não existir; o de `/` ([homeRoute.ts](src/components/Home/homeRoute.ts)) grava o salvamento pendente (`flushBoardSave`) e lê a lista. O `shouldRevalidate` do board só recarrega quando o id muda, porque recarregar zera o histórico.
- **Modelo** ([src/lib/elements/types.ts](src/lib/elements/types.ts)): `BoardElement` é uma união discriminada por `type` (`rectangle`, `ellipse`, `diamond`, `arrow`, `freedraw`, `text`). Todo elemento tem `x, y, width, height` (a caixa delimitadora, sempre normalizada), além de `rotation`, `style` e `seed`. O `seed` é obrigatório: o roughjs sorteia o traço a cada desenho, e sem um seed fixo a forma "treme" a cada redesenho. Seta e lápis guardam `points` **relativos a `x, y`**, então mover qualquer elemento é só mudar `x` e `y`.
- **Formas** (`src/lib/elements/shapes/`): cada módulo exporta um `ShapeUtil` ([shapeUtil.ts](src/lib/elements/shapeUtil.ts)) com `draw`, `hitTest` e `resize`, além das funções de criação e atualização. [registry.ts](src/lib/elements/registry.ts) despacha pelo `type` e cuida do que é comum a todos, como a rotação, a busca do elemento sob o ponteiro e o deslocamento. Para adicionar uma forma: criar o módulo, incluir o tipo na união `BoardElement` e registrar o util em `shapeUtils` (o tipo mapeado faz o TypeScript reclamar se faltar).
- **Setas ligadas** ([src/lib/elements/bindings.ts](src/lib/elements/bindings.ts)): `ArrowElement` tem `startBinding`/`endBinding` (`{ elementId, anchor, fixed }`). As formas que aceitam ligação implementam `getBorderOffset` e `getConnectionPoints` (pontos fixos relativos, que viram o `anchor`) no `ShapeUtil`. A store chama `updateBoundArrows` dentro de `updateElements`, `replaceElement` e `deleteElements`, então qualquer mudança numa forma já reposiciona as setas ligadas a ela. Não recalcule ligações nas interações. Toda ponta ligada sai de um ponto de conexão. Com `fixed: true` (a ponta foi solta sobre o ponto), o ponto fica preso; com `fixed: false` (solta no corpo da forma), o recálculo troca o `anchor` pelo ponto virado para a outra ponta. As interações ligam pontas com `bindArrowEnd`, que trata os laços (as duas pontas na mesma forma). O `updateBoundArrows` recebe os elementos de antes para mover os pontos do meio de um laço junto com a forma. A seta tem `routing` (`straight`, `curved` ou `elbow`). Na reta e na curva, os pontos do meio são do usuário (alças do meio em `getArrowHandles`), e a curva é uma Catmull-Rom que passa por eles (`getArrowPath` amostra a curva para clique e caixa). Na ortogonal, os pontos do meio são derivados das pontas pelo `refreshArrow` (rota em [src/lib/geometry/orthogonalRoute.ts](src/lib/geometry/orthogonalRoute.ts)). Os trechos que o usuário arrastou ficam em `fixedSegments`, e o recálculo liga as pontas e os trechos fixos com pedaços de rota automática. As pontas têm formato próprio (`startArrowhead`/`endArrowhead`), com a geometria pura em [src/lib/elements/arrowheads.ts](src/lib/elements/arrowheads.ts), usada pelo canvas e pelos ícones do painel. Formatos novos entram em `ARROWHEADS` e em `getArrowheadParts`.
- **Rótulos**: retângulo, elipse, losango e seta têm um `label` opcional (`{ text, textStyle }`, veja `isLabeledElement`), desenhado e testado no clique de forma comum em `registry.ts` (`getLabelLayout`). Cada forma define a área do texto com `getLabelArea`. Na seta, a área é uma faixa de altura zero no meio do caminho, e o `renderElement` recorta a linha atrás do texto com `ctx.clip`. A quebra de linha (`wrapText` em [src/lib/text.ts](src/lib/text.ts)) imita o `<textarea>` com `pre-wrap`; se mudar uma, mude a outra.
- **Grade de fundo** ([src/lib/render/grid.ts](src/lib/render/grid.ts)): só visual, sem encaixe (o snap foi testado e descartado). `showGrid` e `gridStyle` (`dots` ou `lines`) ficam na store e são salvos. O `renderScene` desenha a grade antes dos elementos.
- **Coordenadas** ([src/lib/viewport.ts](src/lib/viewport.ts)): os elementos vivem em coordenadas de mundo, e os eventos chegam em coordenadas de tela (pixels CSS relativos ao canvas), com `tela = mundo * zoom + offset`. Converta os pontos do ponteiro com `screenToWorld` antes de criar ou alterar elementos. `renderScene` aplica o viewport e o `devicePixelRatio` via `ctx.setTransform`, então os `draw` desenham direto em coordenadas de mundo. Tamanhos que devem ser constantes na tela (alças, folga de clique, linhas da seleção) são definidos em pixels e divididos por `zoom`. O zoom pelos botões e atalhos do `ZoomIndicator` anda pelos níveis de `ZOOM_STEPS` (`stepZoom`/`resetZoom` da store, centrados no meio da janela); a roda e a pinça continuam livres.
- **Seleção** ([src/lib/selection.ts](src/lib/selection.ts)): o quadro da seleção (`SelectionFrame`, caixa sem rotação mais o ângulo; gira junto quando há um elemento só), as 8 alças, a alça de rotação e a matemática de redimensionar e girar. `getElementBounds` é a caixa alinhada aos eixos, já considerando a rotação; `getElementBox` é a caixa sem rotação. Setas nunca têm `rotation`: girá-las gira os pontos. [renderScene.ts](src/lib/render/renderScene.ts) desenha essa camada por cima dos elementos. Durante o redimensionamento e a rotação, o Canvas preenche o `measurement` do overlay, e [measurement.ts](src/lib/render/measurement.ts) desenha a pílula com as dimensões ou o ângulo.
- **Persistência** ([src/lib/persistence.ts](src/lib/persistence.ts)): cada board fica numa chave própria do `localStorage` (`whiteboard:board:<id>`, com `name`, `elements` e `viewport`), listado no índice `whiteboard:boards` (id, nome, criação e última edição). As preferências da grade ficam à parte, em `whiteboard:preferences`. A store guarda o `boardId` aberto, e a inscrição no fim de `boardStore.ts` salva o board com debounce (só quando o `boardId` não mudou, para a troca de board não contar como edição). Quem sai do board ou troca de board chama `flushBoardSave` antes. O board e pode ser exportado e importado como `.whiteboard.json` (`serializeBoardFile`/`parseBoardFile`; o download e a escolha do arquivo ficam em [src/lib/boardFile.ts](src/lib/boardFile.ts), e as ações da interface em [boardFileActions.ts](src/components/Board/boardFileActions.ts)). O nome do board (`name` na store, editado no [BoardTitle](src/components/Board/BoardTitle/BoardTitle.tsx)) vai nos dois e dá nome ao arquivo baixado. Os dois usam a mesma validação: ao mudar o modelo dos elementos, ajuste o `isValidElement`. Sem versão nem migração durante o desenvolvimento.
- **Exportar imagem** ([src/lib/export/](src/lib/export/)): PNG e SVG usam o mesmo `renderElement` do canvas. O SVG passa um `SvgContext` (imitação parcial do `CanvasRenderingContext2D`) no lugar do contexto, e o roughjs recebe um canvas falso que devolve esse contexto. Se uma forma passar a usar uma operação do contexto que o `SvgContext` não tem, acrescente-a lá. As fontes do SVG são embutidas como subconjunto do Google Fonts ([fonts.ts](src/lib/export/fonts.ts)). O diálogo fica em [Export/](src/components/Board/Export/).
- **Estado e histórico** ([src/store/boardStore.ts](src/store/boardStore.ts)): store do zustand com `elements`, `selectedIds`, `tool`, `viewport` e o histórico (`past`/`future`, snapshots imutáveis de `elements`). Ações discretas (`addElement`, `replaceElement`, `deleteElements`) já registram um passo. Ações contínuas usam `updateElements` sem registrar, e quem chama guarda `elements` no início do arraste e chama `commitHistory(before)` no fim. Sempre crie arrays e objetos novos ao alterar elementos, porque o histórico depende de imutabilidade.
- **Canvas** ([src/components/Board/Canvas/Canvas.tsx](src/components/Board/Canvas/Canvas.tsx)): é dono do `<canvas>` e dos eventos de ponteiro, roda e espaço. Cada arraste é uma `Interaction` (união discriminada em um ref): pan, criação, lápis, mover, redimensionar ou seleção por caixa. Estado transitório (rascunho, caixa de seleção, texto em edição) fica local no Canvas, não na store. Os handlers leem a store com `useBoardStore.getState()` para não depender de closures antigas. A roda usa um listener nativo com `passive: false`, porque o `onWheel` do React não permite `preventDefault`.
- **Texto** ([TextEditor.tsx](src/components/Board/TextEditor/TextEditor.tsx), [src/lib/text.ts](src/lib/text.ts)): a edição usa um `<textarea>` posicionado sobre o canvas, e o elemento em edição é escondido do canvas. Todo texto (solto, rótulo e seta) tem um `TextStyle` (família, tamanho, cor, negrito, itálico e alinhamentos). `fontString`, `LINE_HEIGHT`, `measureText` e `layoutText` recebem esse estilo e são compartilhados entre o canvas e o textarea, para os dois ficarem alinhados. A cor `null` herda o `strokeColor` do elemento (`resolveTextColor`). Mudanças de estilo de texto passam por `applyTextStyle` ([src/lib/elements/textStyle.ts](src/lib/elements/textStyle.ts)), que remede o texto solto.
- **Barra de estilo** ([StyleBar.tsx](src/components/Board/StyleBar/StyleBar.tsx)): barra flutuante renderizada pelo Canvas acima da seleção (ou no topo, com uma ferramenta de desenho ativa e nada selecionado), escondida durante arrastes e edição de texto. Cada botão abre um submenu (`Popover`) com os controles de um grupo ([StyleControls.tsx](src/components/Board/StyleBar/StyleControls.tsx)): contorno, preenchimento e seta. O estilo tem campos separados para contorno (`stroke*`) e preenchimento (`fill*`), e as formas de caixa desenham os dois em etapas separadas (`drawFillAndStroke`). O que cada tipo de elemento aceita fica em [src/lib/elements/style.ts](src/lib/elements/style.ts) (`supportsStyle`). O estilo das próximas formas é o `currentStyle` da store, aplicado na criação pelo Canvas. Mudanças contínuas (seletor de cor, hex, opacidade) usam `setStyle(patch, { record: false })` e um `commitHistory` no fim (`useStylePreview`). Os seletores do zustand ([selectors.ts](src/components/Board/StyleBar/selectors.ts)) devolvem valores simples (string, número), não arrays novos, para não re-renderizar à toa.
- **Cabeçalho do board**: no canto superior esquerdo, o botão de voltar para a lista e o menu do board ([BoardMenu.tsx](src/components/Board/BoardMenu/BoardMenu.tsx): abrir e salvar arquivo, exportar imagem e renomear), seguidos do nome. Ações sobre o board inteiro entram nesse menu, não na toolbar, que fica só com ferramentas, edição e grade (e rola se não couber na altura).
- **Toolbar e atalhos**: [tools.ts](src/components/Board/Toolbar/tools.ts) é a fonte única das ferramentas (ícone, nome e teclas), usada pela toolbar, pela ajuda e por [useShortcuts.ts](src/components/Board/useShortcuts.ts). Os demais atalhos ficam em [shortcuts.ts](src/components/Board/shortcuts.ts) (nome e teclas, mais `formatShortcut` para os tooltips), lidos pelos tooltips e pela ajuda ([Help/](src/components/Board/Help/)). O `useShortcuts` trata as teclas à mão: ao criar ou mudar um atalho, atualize os dois. Os atalhos ignoram teclas digitadas em campos de texto (`isTypingTarget`).
- Tipos primitivos compartilhados (`Point`) ficam em `src/lib/types.ts`, e a geometria pura em `src/lib/geometry/` (`bounds.ts`, `distance.ts`, `constrain.ts`).
- **Primitivos de UI** (`src/ui/`): componentes visuais pequenos e reutilizáveis (`IconButton` com tooltip e atalho, `Tooltip`, `Popover`, `Menu` (lista de ações sobre um `Popover`, com navegação pelas setas), `Modal`, `Toast`, `Button` (padrão, primário e perigo), `InlineEdit` (texto que vira campo com duplo clique), `Panel`/`PanelSection`, `Divider`). Botões de ícone novos devem usar o `IconButton`, e os que abrem um `Popover` passam `hasPopup` (marcador no canto e `aria-expanded`; com `popupRole="menu"` quando abrem um `Menu`). O `Modal` cuida do foco (preso enquanto aberto) e barra os atalhos do board com `stopPropagation`.
- **Tema** ([src/lib/theme.ts](src/lib/theme.ts)): fonte única de cores, fontes, raios e sombras. `applyTheme` (chamado em `main.tsx`) vira cada valor em variável CSS (`--color-*`, `--canvas-*`, `--font-*`, `--radius-*`, `--shadow-*`), e o canvas lê `theme` direto. Não escreva cores, fontes ou sombras soltas em SCSS ou no canvas: use as variáveis ou acrescente um token ao tema. A paleta de cores oferecida aos elementos fica em `theme.palette`.
- **Fontes**: as três vêm do Google Fonts num único `<link>` no [index.html](index.html) (`display=swap`), todas com licença SIL Open Font License.
  - **Caveat** (pesos 400 a 700, variável, sem itálico; o navegador inclina sozinho): token `theme.font.hand` (`--font-hand`). Texto no canvas com a chave `hand`, a padrão.
  - **IBM Plex Sans** (400, 500, 600 e 700, mais itálico 400 e 700): token `theme.font.ui` (`--font-ui`). Fonte da interface (`src/index.css`; os pesos 500 e 600 são dela) e texto no canvas com a chave `sans` (400, 700 e os itálicos).
  - **IBM Plex Mono** (400, 500 e 700, mais itálico 400 e 700): token `theme.font.mono` (`--font-mono`). Na interface, atalhos dos tooltips, badges e campos de hex e tamanho (peso 500); no canvas, a chave `mono`.
  - No canvas, a chave do `TextStyle` vira a família por `FONT_STACKS` ([src/lib/text.ts](src/lib/text.ts)). O Canvas pré-carrega todas as combinações de `FONT_FAMILIES` com negrito e itálico ao abrir e redesenha a cada `loadingdone`, para nenhum texto ser medido com a fonte reserva.
  - Para trocar ou acrescentar uma fonte ou um peso: ajustar o `<link>` do `index.html`, o token em `theme.font` e, se for fonte de texto do canvas, a chave em `FONT_FAMILIES` (`types.ts`), o `FONT_STACKS`, o `GOOGLE_FONTS` da exportação SVG ([src/lib/export/fonts.ts](src/lib/export/fonts.ts)) e o nome no grupo "Texto" da barra de estilo (`TextControls.tsx`).

Estilos: os componentes usam arquivos `*.module.scss` na mesma pasta. Os estilos globais ficam em `src/index.css` e `src/App.css`.

## Convenções

- **Não escreva comentários no código**, nem de linha, nem de bloco, nem JSDoc, em `.ts`, `.tsx` e `.scss`. O código deve se explicar pelos nomes. O motivo das decisões fica nas mensagens de commit (com os detalhes de implementação) e, quando a decisão orienta o trabalho futuro, na seção "Decisões tomadas" do [ROADMAP.md](ROADMAP.md). Se um bloco só fazia sentido com um comentário (por exemplo, um `catch` vazio), reescreva o código para não precisar dele.
- Mensagens de commit e alguns identificadores são escritos em português (pt-BR).
- Componentes usam named exports (`export function Board()`). A exceção é `App`, que é export default.
